## Acceptance criteria (from the spec, verbatim)
- AC-1 WHEN a film run is started, the system shall go from the first pre-take check to the last take with no keyboard, pointer or prompt input from a person. — proof: e2e
- AC-2 IF any pre-take check fails, THEN the system shall stop before opening any live session and name the failed check. The checks, from the screenplay's "Before the take": the Specialist Training latest card is `20261024T180110Z-b501e4a3`; the coach box shows v1 `20261024T174839Z-6f4ab3b5` → v2 `20261024T180110Z-b501e4a3`; the brief agent `brief-onboarding-buddy-b948ed` shows v3 `20261024T183254Z-a5b00df6`; **Avatar (optional)** is unticked; every narrator, T1 and T2 stem is cached with its duration. — proof: red-first integration
- AC-3 WHILE a run is in progress, the system shall send no request that starts a gate run, a coach run, a single-scenario check, a brief proposal, a proposal save or an avatar session. — proof: red-first integration
- AC-4 IF the page issues one of the requests in AC-3 during a run, THEN the system shall block that request, end the run and report which request was blocked. — proof: red-first integration
- AC-5 WHEN a run ends, for any reason, the system shall leave every stored Eval Card and coach record byte-identical to its state at run start. — proof: red-first integration
- AC-6 The system shall record the film without any change to how the demo page or its server behave. — proof: red-first integration [NEEDS CLARIFICATION: Q-HOOK, only if the plan's spike finds the output tap impossible without a page hook]
- AC-7 The system shall produce every narrator and caller line with Higgs TTS 3 and a preset listed in F22. — proof: red-first unit
- AC-8 WHEN auditions are requested, the system shall produce one clip per narrator candidate (`eleanor`, `nora`, `oliver`, `marcus`, per the screenplay) and one clip per caller candidate (the six F22 presets), each named by its preset. Narrator candidates speak the beat 1 line; caller candidates speak T1 (default, Glib may change). — proof: red-first unit
- AC-9 IF the narrator preset or the caller preset has not been named by the operator, THEN the system shall refuse to generate stems and say which preset is missing. — proof: red-first unit
- AC-10 IF the operator names the same preset for narrator and caller, THEN the system shall refuse and ask for two different presets. — proof: red-first unit
- AC-11 WHEN a stem is requested whose text, voice and TTS model match a cached stem, the system shall reuse the cached stem and send no TTS request. — proof: red-first unit
- AC-12 WHEN a stem is requested whose text, voice or TTS model differs from every cached stem, the system shall generate a new stem and keep the earlier one. — proof: red-first unit
- AC-13 WHEN a stem is cached, the system shall record its duration next to it. — proof: red-first unit
- AC-14 IF TTS answers 429 (F26), THEN the system shall retry at most 3 times, waiting 2 s, 4 s and 8 s (no wait longer than 8 s), and after the last refusal stop with a reason that names the line, without writing a partial stem: at most 4 requests in total (Glib, 2026-10-24). — proof: red-first unit
- AC-15 IF a T2 stem holds an internal silence at or above the server VAD silence window (F8), THEN the system shall refuse to use it in a take and name the gap. — proof: red-first unit
- AC-16 WHEN a run is started, the system shall accept a take count from 3 to 5 and refuse any other count before opening a live session. — proof: red-first unit
- AC-62 WHILE a run is in progress, the system shall record exactly the requested number of takes, and not stop early at the first candidate; only AC-28 and AC-29 end a run sooner. — proof: red-first unit
- AC-63 IF a run is started while another run is in progress, THEN the system shall refuse the second run before it opens any live session or writes to the take log. — proof: red-first integration
- AC-17 WHILE a take runs, the system shall supply the page's microphone with a stream that carries only the caller stems the recorder plays and silence between them. — proof: e2e
- AC-18 WHEN the page reports the live session ready, the system shall play T1 into the microphone. — proof: red-first unit
- AC-19 WHEN the first assistant audio of the reply to T1 reaches the page, the system shall start T2 1.5 s later, whatever the reply's length. — proof: red-first unit
- AC-20 IF the reply to T1 has finished playing before T2 is due, THEN the system shall mark the take dropped with reason "T1 reply ended before T2". — proof: red-first unit
- AC-21 IF no assistant audio for the reply to T1 arrives within 10 s after T1 ends, THEN the system shall end the take and mark it dropped with reason "no reply to T1". — proof: red-first unit
- AC-22 The system shall judge "audio stopped on T2" true only when the page signals the start of the trainee's speech while the T1 reply is still playing, and no audio of the T1 reply plays after that signal. — proof: red-first unit
- AC-23 WHEN a take ends, the system shall record the stop latency: from the start of T2 to the last audio of the T1 reply the page played. — proof: red-first unit
- AC-24 IF more than one assistant response follows T2, THEN the system shall flag the take "T2 split into N responses" in the take log, for Glib's listen. — proof: red-first unit
- AC-25 WHEN the reply to T2 completes, the system shall record its transcript in the take log and shall not judge its content; Glib judges by ear whether it refuses and offers to go back to the policy (Glib, 2026-10-24). — proof: red-first unit
- AC-26 The system shall mark a take candidate only when AC-22 is true and no earlier drop reason applies, and otherwise mark it dropped with every failed condition named. — proof: red-first unit
- AC-59 WHEN Glib marks a take as the keeper, the system shall record the mark in the take log, and IF that take is not a candidate, THEN refuse the mark and name its drop reasons. — proof: red-first unit
- AC-27 IF a take's live session ends before the reply to T2 completes, THEN the system shall mark the take dropped with the end reason the page received. — proof: red-first unit
- AC-28 IF a take ends with "quota refused" (F13), THEN the system shall start no further take in that run. — proof: red-first unit
- AC-29 IF the page shows the "not released" banner during a take, THEN the system shall end the take, mark it dropped "not released" and start no further take. — proof: red-first integration
- AC-30 WHEN a take ends, the system shall append one take log entry with: take number, start time, candidate or dropped, every reason, any "T2 split" flag, the actual T2 offset, the stop latency, the T2 reply transcript, the live TTFA values shown and the session end reason. — proof: red-first unit
- AC-31 WHEN a take ends, the system shall hold one audio track with the caller lines as fed and the agent audio as the page played it, cut at barge-in. — proof: e2e
- AC-32 The system shall keep a take's audio and picture aligned within 100 ms. — proof: browser (main session)
- AC-33 The film shall contain the screenplay's eight beats in its order, each with the picture source the screenplay gives it. — proof: browser (main session)
- AC-34 WHEN the timeline is computed, the system shall make each beat as long as its narrator line plus a 0.4 s lead and a 0.6 s tail. Beat 7 is narrator intro, then the take, then narrator outro. — proof: red-first unit
- AC-35 The system shall never place a narrator stem over the take audio. — proof: red-first unit
- AC-36 WHEN the timeline is computed, the system shall report each beat's length against the screenplay's target and the total against 180 s. — proof: red-first unit
- AC-37 IF the total exceeds 180 s, THEN the system shall refuse the render and report the overrun per beat (180 s is a hard cap). — proof: red-first unit
- AC-38 WHILE beat 5 plays, each highlight (v1 REJECTED 4/6 and the two failed skills, the rewritten procedures, v2 RELEASED 6/6 and both run ids) shall appear when the narrator sentence that names it starts, within ±0.5 s. — proof: red-first unit
- AC-39 WHILE beats 4–6 are recorded, the system shall open no live session. — proof: red-first integration
- AC-40 WHILE a caller line plays in beat 7, the system shall show its screenplay text as a caption for the line's duration. — proof: red-first unit
- AC-41 WHEN the reply to T2 completes, the system shall caption it with the text the page received for that reply, shown as plain text. — proof: red-first unit
- AC-55 WHILE the interrupted reply to T1 plays, the system shall caption it "(interrupted)" and never with text the agent did not speak (F27). — proof: red-first unit
- AC-61 WHILE a narrator line plays in any beat, the system shall show its screenplay text as a caption for the line's duration. — proof: red-first unit
- AC-42 WHILE beat 7 plays, the live TTFA value and its label shall stay inside the frame. — proof: browser (main session)
- AC-43 The graphic beats shall take their text only from the same line data the claims gate checks, and that text shall match the screenplay word for word, including `REJECTED · 4 / 6`, the run ids and the attribution of "Agents that coach themselves" to boson.ai. — proof: red-first unit
- AC-60 IF a rendered graphic beat is missing, or its length differs from its timeline slot by more than one frame, THEN the system shall refuse the final render and name the beat. — proof: red-first integration
- AC-44 WHILE the market beat plays, Boson's row shall light across speech-to-speech, text-to-speech and real-time avatar. — proof: browser (main session)
- AC-56 WHILE the hook beat plays, the film shall carry one low tone under the narrator. — proof: browser (main session)
- AC-45 WHEN beat 8 is recorded, the system shall show `boson-ai/ihbench` pull request 2, then the hand-off document, then the end card; the narration calls the PR "a draft pull request to Boson's repo" (screenplay, Glib 2026-10-24). Both the PR page and the hand-off document are shown from captured images, never from live GitHub during a run. — proof: browser (main session)
- AC-46 WHEN a final render is requested, the system shall run the claims gate first, and IF it fails, THEN render nothing and list every failing line. — proof: red-first integration
- AC-47 The claims gate shall treat digits and English number words, including "a cent", as numbers, and fail every narrator, graphic or end-card line holding a number that maps to no CLAIMS row. — proof: red-first unit
- AC-48 The claims gate shall pass a mapped row only when its status is `ok` or starts with `ok` followed by a note in parentheses. — proof: red-first unit
- AC-49 The claims gate shall pass a run id or agent id shown or spoken only when it appears in the evidence of its mapped CLAIMS row. — proof: red-first unit
- AC-50 The claims gate shall fail the market line ("Of the companies we compared…") until a CLAIMS row for it exists with status `ok`. — proof: red-first unit
- AC-51 WHEN the final render is requested, the system shall use the take Glib marked as the keeper, and IF no take carries the keeper mark, THEN refuse. — proof: red-first unit
- AC-52 WHEN the claims gate passes and a keeper is marked, the system shall produce one film file holding the picture of every beat, the keeper take's audio and the narrator stems at their timeline positions. — proof: e2e
- AC-57 The film's mixed audio shall measure −16 LUFS integrated (Glib, 2026-10-24). — proof: red-first integration
- AC-58 The film shall be 1920×1080 at 30 fps (Glib, 2026-10-24), unless the pending capture research shows the page recording cannot reach it; then this AC is revisited with Glib, not lowered silently. — proof: red-first integration
- AC-53 The system shall keep every API key out of the take log, captions, stems, auditions and the film. — proof: red-first unit
- AC-54 The offline test suite shall prove the timeline math, the take rule, the claims gate and the stem cache with no network, and every check that opens a Boson session or calls TTS shall carry the `live` marker. — proof: red-first integration

## Risks
- Chromium may throw on cross-rate `createMediaStreamSource`, which is why the fake stream is built in the page's own 24 kHz context. Headless `--mute-audio` might starve the tap; the spike proves or disproves both (S-3, S-5).
- Playwright page video frame rate and bitrate, and the alignment between video and tap (AC-32, AC-58): dispatch `research-tools:researcher` for Playwright `recordVideo` fps/quality and CDP `Page.startScreencast` timestamps as the fallback. AC-58 stays open as the spec has it.
- Remotion: whether the CLI/renderer downloads a headless browser on its first render (network); the exact `bundle`/`renderMedia` input-props API for the pinned version; the license terms for an individual or hackathon use. Dispatch `research-tools:researcher` before step 21.
- A local ffmpeg without `drawtext`/`subtitles` (seen in an earlier project): step 1 decides the caption writer. If neither filter exists, Glib must install another build (blocking for captions only).
- The offline network guard in `tests/conftest.py` applies to the whole suite. If an existing offline test reaches beyond loopback, it fails, and lane 0's gate run shows it.
- Per-sentence stems may sound choppier than one stem per beat; Glib judges by ear in step 24.
- A take's T1 reply may be shorter than 1.5 s (persona caps answers at two sentences), so some takes drop by design (AC-20). Five takes is the upper bound.
